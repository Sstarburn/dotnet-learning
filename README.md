## 0. 摸底结论:你在哪一级

**当前位置:约 L1 → L2 之间,典型"能改不会写"。**

| 维度 | 现状 | 判断 |
|---|---|---|
| C# 语法 | 项目里改过代码 | 能读能改,不能从零写 → 手熟度问题,不是智商问题 |
| 状态机 | 见过多种写法,"说不清" | 概念模糊 + 没练过建模 → 放进 L4 专项解决 |
| 委托与事件 / LINQ / 泛型 | 基本没接触 | 日常高频,必须从 L2 补 |
| async/await | 有概念 | L3 深入,这是上位机通信的命脉 |

> 一句题外话:C# 是语言,.NET 是平台——可以粗略类比成"Java 语言 + JVM/生态"。我们要练的是 C# 这门语言,在 .NET 平台上跑。

### 为什么你写不出状态机(对症下药)

1. **输入 : 输出严重失衡** —— 平时 90% 时间在读代码,手指几乎没有"从零写"的记忆;
2. **缺建模训练** —— 总在看成品代码,没练过"需求 → 状态图 → 代码"这一条路;
3. **想一步写出完整版** —— 一上来就对标复杂实现,自然下不了手。

> 处方:**每日默写 + 状态图先行 + 从 20 行最小版本迭代**(见 §4、§6)。

## 1. 五级地图

| 级别 | 主题 | 核心内容 | 出关标准(关资料写出来) |
|---|---|---|---|
| L1 | 语法复活 | 类型(值/引用)、控制流、集合(List/Dictionary)、方法、类与属性、枚举、异常 | 控制台小工具:设备管理器 |
| L2 | C# 惯用法 | 属性精讲、泛型、接口/抽象类、委托 + lambda、**事件 event**、LINQ、扩展方法、模式匹配 | 事件驱动小程序:模拟"按钮 + 数据到达" |
| L3 | 异步与并发 | async/await、Task、CancellationToken、定时器、线程与锁、跨线程更新 UI | 可取消的"周期采集器";看懂"async 方法编译后也是状态机" |
| L4 | **状态机专项(旗舰)** | 状态 / 事件 / 转移 / 守卫 / 动作;switch 版 → 状态模式 → 泛型状态机 → 设备实战;设计模式(状态/工厂/观察者) | 设备状态机:空闲→运行→暂停→报警→复位,拒绝非法转移 |
| L5 | 工程化与方向 | 依赖注入、配置、日志、单元测试、调试;串口 / TCP / 协议解析;WPF + MVVM 入门 | 迷你上位机:模拟设备 → 采集 → 状态显示 → 控制 |

> 冷知识:L3 里的"状态机"指 **async/await 编译后生成的状态机**(编译器魔法);L4 才是你要攻的"**状态机模式**"。两个同名不同物,学到 L3 时你会心一笑。

## 4. 每天 1 小时怎么用(升档后)

**黄金配比 10 / 25 / 25:**

| 时段 | 做什么 |
|---|---|
| 0–10 min | **默写昨天**:关掉所有资料,把昨天的核心代码重写一遍。卡住 → 看 30 秒 → 再关掉继续写 |
| 10–35 min | 学 + 敲今天的新知识点(边看边敲,不空看) |
| 35–60 min | **独立练习**:改需求,或不看资料加一个小功能 |

**三条铁律:**

1. **输入 : 输出 ≥ 1 : 3** —— 每看 1 分钟,至少动手 3 分钟(你现在最缺的就是这个);
2. 每个知识点当天必须"关掉资料写出来"一次,**写不出来不算学过**;
3. 每周日重写本周代码,卡壳点记下来——**卡壳点 = 你的真实水平线**。

> 忙的日子回落到 30 分钟版(配比 5 / 15 / 10)——**宁可短,不可断**。

## 6. 状态机专项(第 3 周,提前剧透)

**概念五件套:状态(State)、事件(Event)、转移(Transition)、守卫(Guard)、动作(Action)。**
状态机不神秘——它就是**"表格化后的 if/else"**:什么状态下、收到什么事件、满足什么条件、跳到什么状态、顺手做什么。

**五步递进(每题先画状态图,再写代码):**

| 版本 | 做法 | 关键收获 |
|---|---|---|
| v1 | `enum` + `switch`,红绿灯:红→绿→黄→红 | 最小心智模型,20 行 |
| v2 | 加事件与守卫:行人按钮、黄灯时长;非法转移要拒绝 | 转移条件、守卫 |
| v3 | 状态模式:`ILightState` 接口,每个状态一个类 | OO 抽象、开闭原则 |
| v4 | 泛型状态机:`StateMachine<TState, TEvent>` + 转移表(Dictionary) | 可复用组件;回头看 `stateless` 库的 Fluent API 秒懂 |
| v5 | 设备实战:Idle / Running / Paused / Alarm / Resetting;事件 Start / Pause / Resume / Fault / Reset;动作记日志、发通知 | 上位机真实场景 |

**建模流程(固定动作,治"写不出来"):**

> 需求 → ① 画状态图 → ② 列转移表(状态 × 事件) → ③ 写 20 行最小版 → ④ 逐条加需求迭代
